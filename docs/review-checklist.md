# Code Review Checklist

Use this short checklist every time you open a review request. A good review is timely, specific, and kind.

## Before you comment

- Read the whole diff before commenting on any single line.
- Check the pull request description and any linked issue for context.
- Run the changes locally if tests are not already green.
- Ask yourself whether the concern is blocking or just a preference.

## While you comment

- Quote the exact line you are commenting on
- Separate must-fix items from nice-to-have suggestions.
- Praise good work explicitly, not just problems.
- Offer a concrete alternative instead of only describing the problem.
- Keep the tone about the code, never about the person.

## After you comment

- Confirm whether you approve, request changes, or are simply leaving comments.
- Offer to pair or answer follow-up questions.
- Follow the pull request through to merge so nothing is left ambiguous.
